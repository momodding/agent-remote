## Context

Multi-shell mode currently renders every non-minimized session as a stacked pane, places its shortcut keyboard over the bottom of that grid, and limits sessions through `getPlatformMax()` to four on web or two on native. Requested end state: readable add-session glass, a sheet that expands and scrolls above the keyboard, up to five open shell tabs with at most two terminals visible in split mode, guided drag-and-drop split arrangement, top tabs clear of the shortcut bar, compact icon actions beside the multi-terminal title, and long text actions replaced by recognizable icons.

## Approach

1. **Make the shared glass sheet readable and able to reach the top.** In `client/src/components/GlassBottomSheet.tsx`, keep `BottomSheetModal`, `BlurView`, safe-area insets, backdrop, and the caller-supplied `BottomSheetScrollView` contract. Set `GLASS_BLUR_INTENSITY = 90`; give the blur surface `rgba(10,10,10,0.82)` in dark mode and `rgba(250,250,250,0.86)` in light mode so text contrast does not depend on device blur quality. Replace dynamic-only sizing with `enableDynamicSizing={false}` and memoized snap points `['55%', '100%']`; preserve `topInset`, `bottomInset`, `keyboardBehavior="interactive"`, `keyboardBlurBehavior="restore"`, and `android_keyboardInputMode="adjustResize"`. In `client/src/components/AddSessionFAB.tsx`, keep form fields and shell options in `BottomSheetScrollView`, add `style={{ flex: 1 }}`, keep `keyboardShouldPersistTaps="handled"`, and include `bottomInset + 24` in content padding so the last shell and submit action remain reachable with the keyboard open. Empty or failed shell discovery still leaves “Default shell” selectable; session creation errors remain alerts and do not dismiss the sheet.

2. **Model five open tabs separately from the one-or-two visible panes.** In `client/src/lib/multi-session.ts`, replace `getPlatformMax()` with `export const MAX_MULTI_SESSIONS = 5` and remove the now-unused `Platform` import; callers compare counts to that constant. Remove `minimized` from `MultiSessionState`, delete `toggleMinimize()`, and update all fixtures/callers in a clean cutover. Add exact pure layout types and reducer for component use and direct tests: `export type SplitSide = 'left' | 'right'`, `export type SplitLayout = { left: string | null; right: string | null }`, and `export function placeInSplit(layout: SplitLayout, sessionId: string, side: SplitSide): SplitLayout`. Rules: from one visible tab, dropping another into either side places the existing tab opposite it; from a full split, an inactive tab replaces only the target side while the displaced session remains open as a tab; dragging either visible pane to the opposite side swaps the two panes; dropping it on its current side is a no-op. Add `export function reconcileSplit(layout: SplitLayout, orderedSessionIds: string[]): SplitLayout`: remove IDs not in `orderedSessionIds`, preserve surviving sides, collapse a lone right survivor to `left`, and when neither survives select `orderedSessionIds[0]` on `left` or return both sides null for an empty list.

3. **Render top tabs and at most two terminal panes.** In `client/src/components/MultiTerminal.tsx`, replace the stacked `grid` and minimized strip with a horizontally scrollable tab strip immediately above terminal content. Keep tab order equal to `Object.values(sessions)` insertion order. Local `SplitLayout` starts with the first session on `left`; tapping any tab collapses to that tab alone on `left`, while drag/drop invokes `placeInSplit`. Reconcile layout whenever session IDs change. Render `Terminal` only for non-null layout sides, side-by-side with equal flex when both exist; all other sessions stay connected and retain output but render only their tabs. Keep focused-terminal input/copy/paste/select-all behavior, and focus a pane on tab selection or pane touch. Remove `platformMax`, `onMinimize`, old pane minimize actions, minimized preview styles, and every corresponding caller/test.

4. **Use installed gesture and animation libraries for guided split placement.** In `client/src/components/MultiTerminal.tsx`, use `Gesture.Pan().activateAfterLongPress(250)` and `GestureDetector` from `react-native-gesture-handler` `~2.32.0`, plus `useSharedValue`, `useAnimatedStyle`, `withTiming`, `runOnJS`, and `useReducedMotion` from `react-native-reanimated` `4.5.0`; keep ordinary tab selection on the existing `Pressable.onPress`, and do not add dependencies or Babel changes because `GestureHandlerRootView`, New Architecture, and Expo preset configuration already exist in `client/app/_layout.tsx`, `client/app.json`, and `client/babel.config.js`. Long-press/dragging a tab moves an animated copy, reveals two labeled `Left`/`Right` drop zones over the terminal region, and highlights the zone under the pointer. Measure the terminal region with `measureInWindow`; accept a drop only when `absoluteX`/`absoluteY` is inside that rectangle, choose side by its horizontal midpoint, then call `placeInSplit` through `runOnJS`. Cancel/outside drops restore the tab without changing layout. Animate only translation, scale, opacity, and zone emphasis for 180 ms; when `useReducedMotion()` is true, assign final values without timing. A tab press without the 250 ms hold remains the fully supported non-drag path.

5. **Move multi-terminal actions beside the title.** In `client/app/terminal/[id].tsx`, move broadcast ownership visually into the multi-mode header: title, Feather `zap` broadcast toggle, then Feather `x-circle` close-all. Keep exact accessibility labels `Enable broadcast`/`Disable broadcast` and `Close all`, expose active broadcast with cyan fill plus icon state, and preserve existing broadcast routing and close-all behavior. Remove `MultiTerminal` props `isBroadcasting`/`onBroadcastToggle`, its separate toolbar, visible “Broadcast Input”/“Broadcasting” text, and pane broadcast badges; header state is the single indicator.

6. **Convert every action button that can be represented unambiguously to Feather icons.** Use the existing direct `Pressable`/`TouchableOpacity` plus `Feather` pattern—no new button abstraction—and give every icon-only action a minimum 44×44 hit target, pressed/disabled state, and descriptive `accessibilityLabel`. Apply these exact mappings: dashboard `Connect daemon → link`, `Refresh → refresh-cw`, `Files → folder`, `Daemons → server`, `New shell → plus`, `New multi-session window → columns`, card `Open → external-link`, card `Close → x`; Files screen `Sessions/Files back → arrow-left`, `Refresh → refresh-cw`, `Save/Saving → save` with `ActivityIndicator` while saving; terminal Detach → `arrow-left`, Clear → `trash-2`, Close → `x`; shortcut bar collapsed `Shortcuts → keyboard`, while copy/paste/select-all/collapse retain their existing icons; Add Session FAB `+ → plus`, Create → `check`; Connection sheet Done/Select/Edit/Delete/Add daemon/Cancel edit/Save changes → `check`/`check-circle`/`edit-2`/`trash-2`/`plus`/`x`/`save`, with `ActivityIndicator` while saving; Pairing sheet Cancel/Allow camera/Open camera settings/Retry camera/Use pasted JSON/Scan QR code/Connect → `x`/`camera`/`external-link`/`refresh-cw`/`clipboard`/`camera`/`log-in`, retaining existing busy indicators and disabled states. Keep text for input labels, shell/list content, state/error copy, radio options, native confirmation dialogs, and terminal keycaps (`Ctrl`, `Alt`, Esc, arrows, function keys): these are content or literal key values, not replaceable action labels. Remove styles used only by deleted button text.

7. **Update route and state wiring without changing socket semantics.** In `client/app/terminal/[id].tsx`, keep `multiSocketsRef`, `handleAddSession`, `handleCloseSession`, `handleInput`, `handleResize`, initial-session effect, and REST error handling. Disable `AddSessionFAB` when `Object.keys(multiSessions).length >= MAX_MULTI_SESSIONS`; the existing duplicate-ID guard remains. Closing a tab still closes its socket and daemon session; natural exit removes it and lets `MultiTerminal` reconciliation select the survivor. No backend or wire-protocol change is needed because hidden tabs retain the same per-session sockets and output state.

## Assumptions & contingencies

- `expo-blur` may render weaker blur on some Android devices; implementation must pair stronger blur with a theme-specific translucent surface fill, not rely on blur alone. If `BlurView` still fails on a tested device, keep the opaque fill as readability fallback rather than adding another glass dependency.
- React Native Reanimated 4 requires New Architecture; `client/app.json` already has `newArchEnabled: true`. If Expo web cannot run UI-thread gesture callbacks in the built bundle, preserve the same `GestureDetector` API and use its documented JavaScript-thread callback path for drop-state commit rather than introducing a web-only drag library.
