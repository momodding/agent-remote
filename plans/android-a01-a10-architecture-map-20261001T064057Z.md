## Product architecture relevant once an Android gate reaches the app

### Shared Agent Chat / Raw Terminal invariant

Agent Chat is **one semantic projection of the same normal OMP TUI process** as Raw Terminal—not a second agent, synthetic transcript, ANSI parser, or RPC sidecar.

1. A workspace `AgentWorkspaceTab` contains both `agentSessionId` and its shared `terminalSessionId` (`client/src/lib/tabs/types.ts`).
2. `client/app/agent/[id].tsx` uses `RuntimeChannel.openAgentChannel` for semantic events and `DaemonChannel.subscribe(tab.terminalSessionId, ...)` for raw PTY output. Its Chat/Terminal switch only changes `viewMode`; the terminal ID does not change.
3. Semantic actions route through `AgenticRemoteAPI` to the daemon. Raw input/resize stays on the PTY channel (`client/src/lib/api.ts`, `client/src/lib/daemon-channel.ts`, and `client/src/lib/runtime-channel.ts`).
4. Backend `session.Manager` owns the `TerminalRuntime`, PTY/backend lifecycle, output sequence, subscribers, scrollback, and restore (`backend/internal/session/manager.go`). The recovery architecture requires `AgentSession` to reference—not duplicate—that terminal runtime and OMP process (`plans/recover-agent-architecture.md`, §§22–27 and 44–50).
5. The server keeps terminal bytes on `/v1/ws/sessions/:id`, while runtime semantic events/commands use `/v1/ws/runtime` (`backend/internal/server/server.go`, `handlePTYWS`, `handleRuntimeWS`, `executeCommand`).

**Smallest invariant observation:** create one agent, record its `terminalSessionId`, switch Chat → Terminal → Chat, then prove one OMP PID and that both views retain that same agent/terminal identity. The authoritative plan specifically requires PID counting rather than inferring process count from UI output.

### Sheets, keyboard, and lifecycle

- The root mounts `GestureHandlerRootView` and `BottomSheetModalProvider` in `client/app/_layout.tsx`; sheets use `@gorhom/bottom-sheet` through `GlassBottomSheet` with `keyboardBehavior="interactive"` and Android `adjustResize` (`client/src/components/GlassBottomSheet.tsx`).
- The Agent Chat composer lives in `client/app/agent/[id].tsx`. It only applies `KeyboardAvoidingView` behavior on iOS; Android instead computes `keyboardInset` for the *terminal* shortcut keyboard, not the chat composer. The chat `FlatList` also has no bottom inset tied to a visible composer/IME. This is a concrete candidate if a missing A07/A09 report is an Android composer-obscured-by-keyboard regression; it is not evidence for the E2E A03/A06 infrastructure gates.
- The app shell independently reconciles daemons/runtime state in `client/app/index.tsx` and persists presentation tabs in `client/src/lib/tabs/tab-store.ts`; the recovery architecture says this client state cannot be authoritative for runtime existence.

### noVNC

The recovery architecture requires a short-lived one-use desktop ticket and a direct binary RFB socket. `client/app/desktop.tsx`/`.web.tsx` own the noVNC initialization; `backend/internal/server/server.go` owns ticket issuance and the concurrent RFB proxy pumps. A desktop regression must be observed across this ticket → WebSocket → RFB path, never by treating the JSON runtime or PTY socket as RFB transport.

## Shared-root-cause hypotheses (unproven)

1. **Layer confusion is the primary risk.** A01–A06 are infrastructure gates; treating a later visual/Agent Chat/noVNC symptom as another A-gate would skip the intervening APK, Android system, pairing, daemon, and protocol evidence.
2. **Android readiness needs two contracts.** ADB boot/package readiness is necessary but the ledger's later system-ANR history shows it is not sufficient for stable interaction. Keep emulator-system readiness separate from React Native surface readiness.
3. **Identity splitting would produce apparently independent Chat/Terminal failures.** The client currently has two transport subscriptions, but they must converge on the same `AgentSession`/`terminalSessionId` and one OMP TUI process. Any duplicate agent creation, separate ID, or terminal-derived semantic rendering violates the fixed architecture.
4. **Ticket/transport boundary errors are isolated to Desktop.** RFB failures should be traced through the one-use ticket and direct binary WebSocket, not through Agent Chat or the runtime JSON channel.

### Corrected shared-root-cause grouping (hypotheses)

1. **Client projection reconciliation:** A01, A04, A05, and A10 each cross the agent semantic event/history/cursor projection. Test their event ordering and visibility as one bounded trace, while preserving the fact that Chat is one semantic projection of the same normal OMP TUI process as Raw Terminal.
2. **Native viewport/IME ownership:** A03, A06, A07, and parts of A09 cross safe areas, modal/sheet containers, scroll insets, and Android IME resize behavior. They should be observed on device as related layout contracts, not collapsed into a single visual tweak.
3. **WebView boundaries:** A02 and A08 use different WebViews and different transports: terminal input uses the React Native/WebView message bridge plus PTY; noVNC uses a ticketed direct binary RFB socket. Their failures must not share a transport diagnosis without evidence.
