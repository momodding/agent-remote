## Context

`agenticRemote` today is a working Go daemon (`backend/`) paired with a Flutter reference client (`client/`). The daemon's Auth-v2 pairing/session/PTY/filesystem/notify surface is fully implemented and verified by reading `main.go`, `server.go`, `config.go`, `auth.go`, `pairing.go`, `manager.go`, `protocol.go` in full — real PTY exec, scrollback replay on every `Subscribe()`, and an on-demand `/v1/pairing` mint endpoint all already exist. Two things are missing for the request: (1) `AllowedCIDRs` is parsed/validated in `config.go` but never enforced against real connections anywhere in `server.go`/`main.go`; (2) the client is Flutter, and the ask is a from-scratch Expo/React Native client (Managed Expo Go workflow, confirmed with the user — no bare/custom dev client, no dynamic TLS fingerprint pinning). This plan closes the CIDR gap and replaces `client/` wholesale with an Expo app that reproduces the Flutter client's protocol contracts (Auth-v2 handshake bytes, Argon2id params, diagnostic strings, shortcut-keyboard byte sequences, scrollback-replay-based reconnect) without porting its widget tree.

## Approach

1. **Enforce `AllowedCIDRs` in the backend.** Add a `func (s *Server) allowedCIDR(next http.Handler) http.Handler` in `server.go` that parses `r.RemoteAddr` with `net.SplitHostPort`/`net.ParseIP` and rejects (403, `ErrorEnvelope{Code:"forbidden_source"}`) any request whose IP matches no `net.ParseCIDR` range in `s.cfg.AllowedCIDRs` (empty list = allow all, preserving current default-open behavior for `[]`); wire it into `Handler()`'s existing chain as `logRequests(cors(s.allowedCIDR(mux)))`. Stdlib only, no new deps. This is backend-only and unblocks nothing else, so do it first and in isolation.
2. **Replace `client/` with a fresh Expo (TypeScript, Expo Router, Managed/Expo-Go-compatible) app.** Delete the Flutter tree (`client/lib`, `client/test`, `client/pubspec.yaml`, `client/android`, `client/ios`, etc. — full removal, no dual-maintenance shim) and scaffold via `npx create-expo-app`. Add `nativewind` + `react-native-reusables` for the Shadcn-style UI (already the plan's locked choice), `@noble/hashes` (audited, zero-dep, pure JS — already used for SHA256/HMAC/BLAKE2b) for HMAC-SHA256 and as the primitive base for step 3, and `expo-crypto` (ships in Expo Go, no custom dev client needed) for CSPRNG nonce bytes.
3. **Port the Auth-v2 client crypto exactly**, mirroring `auth.go`/`pairing.go`/`agentic_remote_api.dart`'s `clientProof`: vendor a small first-party `argon2id.ts` (RFC 9106, single-lane since backend calls `argon2.IDKey(token,salt,3,64*1024,1,32)` with `threads=1` — no cross-lane sync needed) built on `@noble/hashes`'s `blake2b` primitive (no pure-JS Argon2id npm package exists — confirmed via repeated targeted search; every hit is a native/WASM wrapper). Validate against the official RFC 9106 Argon2id test vectors before wiring it into the handshake. Build `authHello`/`authProof` framing (`Type,PairingID,ClientNonce,ClientName` / `Type,PairingID,ChallengeID,Proof`) and the HMAC construction `mac(authContext="agenticRemote-auth-v2", pairingId, clientNonce, serverNonce, challengeId)` byte-for-byte matching `auth.go:193-247`. Ship one pairing payload parser (`PairingPayload{Version,Endpoint,Fingerprint,SkipFingerprintVerification,PairingID,Token,ExpiresAt}`) and a fingerprint check that's a no-op whenever `SkipFingerprintVerification` is true or the endpoint isn't self-signed (Managed Expo Go has no per-connection TLS-pinning hook — accepted, user-approved regression scoped to self-signed/direct-LAN endpoints only).
4. **Build the WebSocket session client**: bootstrap over `/v1/ws/sessions/bootstrap` (unauth handshake, closes after `auth.ok`), then `/v1/ws/sessions/{id}` with in-band `AuthToken{Type:"auth.token",Token}` frame per `handlePTYWS`. Base64 encode/decode `pty.input`/`pty.output`, send `pty.resize`, surface `session.state`/`WaitState`. REST layer: bearer token on `GET/POST /v1/sessions`, `/v1/sessions/{id}/close`, `/v1/pairing`, `/v1/fs/*`, `/v1/git/status`, `/v1/notify/register` — plain `fetch`, no client library needed (ponytail: one thin `api.ts` wrapping `fetch`, not a generated SDK).
5. **Terminal**: bundle `xterm.js` + `xterm-addon-fit` as a local static HTML asset loaded into `react-native-webview` (Metro/Expo asset bundling — no CDN fetch, matches existing offline-reliability bias); a `postMessage` bridge carries `{type:"input"|"resize"}` up and `{type:"output"|"clear"}` down, mirroring `terminal_screen.dart`'s `Terminal(maxLines:10000)`/`onOutput`/`onResize` wiring 1:1 in byte semantics, not widget structure.
6. **Reconnect**: use React Native `AppState` — on background, close the session WS; on foreground, reconnect and re-subscribe. No client-side buffer/seq bookkeeping needed: `manager.go`'s `Subscribe()` already replays the full scrollback file on every subscription, so resubscribe-on-foreground is sufficient and correct.
7. **UI**: session dashboard (responsive grid on web / stacked on mobile, search bar, live-preview cards) built on `react-native-reusables` components; connection-diagnostics overlay reusing the exact five strings from `connection_diagnostics_overlay.dart` (`"Resolving endpoint..."`, `"Initiating TLS Handshake..."`, `"Validating Certificate Fingerprint..."`, `"Executing Auth-v2 Challenge..."`, `"Session Established"`); mobile shortcut keyboard reproducing `shortcut_keyboard.dart`'s exact byte sequences and row layout (topRow/symbols/nav/functions, Ctrl/Alt/Shift-Tab modifier toggles, collapse chevron) as a native RN component, not a WebView overlay, so it works over any terminal state. Filesystem browser and Git-status badges implemented fresh against the REST contracts (Flutter's `file_browser.dart` was itself only a placeholder stub — nothing to port there).
8. **Delivery/docs/CI cutover**: `Makefile` — replace `client-test`/`client-build`/`client-build-web`/`run-client` Flutter invocations with Expo/Node equivalents (`npm ci && npx tsc --noEmit && npx jest` for test; `npx expo export --platform web` for web build; `npx expo start` for run-client), keep `CLIENT_TARGETS` parameterization shape; `.github/workflows/ci.yml` — replace the `flutter` job (lines 21-31) with a Node job (`actions/setup-node`, `npm ci`, `npx tsc --noEmit`, `npx jest`); `README.md` and `client/README.md` — rewrite Quickstart/run instructions for `npx expo start`/EAS; `docs/android-daemon-connect.md` lines ~75-79 — swap the `flutter clean/pub get/devices/run` block for Expo equivalents; `AGENTS.md` — update the client architecture/directory-map/testing-command sections to describe the Expo app instead of Flutter. `scripts/install.sh`, `scripts/install.ps1`, `scripts/sha256-manifest.sh` need no changes (backend-binary-only, confirmed by full read).

## Assumptions & contingencies

- No pure-JS Argon2id npm package exists (verified via repeated search); vendoring ~150 lines against RFC 9106 using `@noble/hashes`'s audited `blake2b` is the ponytail-consistent fallback. If the vendored implementation fails RFC test vectors, debug against the spec before wiring it into the handshake — do not ship an unverified crypto primitive.
- Managed Expo Go means no dynamic per-connection TLS fingerprint pinning (locked, user-approved). Self-signed/direct-LAN endpoints require `skipFingerprintVerification:true` in the pairing payload, matching the existing Android-tunnel bypass pattern; public-CA/tunnel/browser-trusted endpoints are unaffected.
- `client/` is fully replaced, not dual-maintained — Flutter source is deleted once the Expo equivalent is verified working end-to-end, per the clean-cutover contract.
- xterm.js ships as a bundled local asset (Metro), not a CDN fetch, for offline reliability; if Expo asset loading into the WebView proves unreliable in practice, fall back to inlining the HTML/JS as a base64 string built at bundle time.
