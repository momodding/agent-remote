## Context
Add client-side management for saved daemon connections: save paired credentials, edit connection metadata, delete saved connections, switch the session dashboard between saved daemons without pairing again, and show only active sessions. When a terminal session exits or the user disconnects, clear and close the terminal/session flow and return to the selected daemon's session list.

## Approach
### 1. Replace single-connection persistence with a selected connection store
- In `client/src/lib/connection.ts`, keep the current storage boundary and key: AsyncStorage on web, SecureStore on native, key `agenticremote.connection`. Replace the stored single `Connection` with `ConnectionStore = { connections: Connection[]; selectedEndpoint: string | null }`; this preserves native bearer-token protection and permits in-place migration.
- Extend `Connection` with local display field `name: string`; retain editable `endpoint`, `fingerprint`, `skipFingerprintVerification`, `token`, and `clientName`. Add `PairedConnection = Omit<Connection, 'name'>` and change `authenticatePairing(...)` in `client/src/lib/api.ts` to return `Promise<PairedConnection>` so the dashboard can attach a daemon display name without weakening the stored type.
- Export these exact storage operations: `loadConnections(): Promise<ConnectionStore>`, `saveConnection(connection: Connection): Promise<ConnectionStore>`, `updateConnection(originalEndpoint: string, replacement: Connection): Promise<ConnectionStore>`, `selectConnection(endpoint: string): Promise<ConnectionStore>`, `deleteConnection(endpoint: string): Promise<ConnectionStore>`, and pure lookup `getConnection(store: ConnectionStore, endpoint?: string | null): Connection | null`. Each mutator performs one read-modify-write against the existing key and returns the persisted store so screens update from the authoritative value.
- Normalize endpoints with `URL`: trim, accept only `http:`/`https:`, require a host, reject credentials/query/fragment and paths other than `/`, then remove the trailing slash. Validate `name` and `clientName` as trimmed 1–64 Unicode code points, require non-empty trimmed token, require string fingerprint and boolean `skipFingerprintVerification`. `updateConnection` uses `originalEndpoint` to find the record, permits changing every field, rejects a replacement endpoint already owned by another record, and rewrites `selectedEndpoint` when the selected record's endpoint changes.
- `saveConnection` upserts by normalized endpoint and selects it. After Auth-v2 pairing, preserve the prior display name when re-pairing an existing endpoint; otherwise use `new URL(endpoint).host`. This makes re-pairing refresh fingerprint/token/client metadata rather than creating a duplicate. `selectConnection` rejects an unknown endpoint. `deleteConnection` preserves `selectedEndpoint` when deleting another record; when deleting the selected record it selects the first remaining record, or `null` when none remain.
- `loadConnections` recognizes the current raw single-`Connection` object, adds the host-derived `name`, wraps and selects it, and immediately writes the new shape. For a valid store whose `selectedEndpoint` no longer exists, select the first record and persist the repair. Missing storage returns `{ connections: [], selectedEndpoint: null }`; malformed or structurally invalid storage is removed and returns the empty store. Native SecureStore errors still surface—never fall back to AsyncStorage. Dashboard/files/terminal bootstrap must catch storage rejection, stop their loading state, alert `Could not load daemon connections`, and route to `/` where applicable; never hang on the loading screen.
- Replace the current cases in `client/src/lib/connection.test.ts` with web/native round trips, legacy migration, same-endpoint upsert, all-field update including endpoint selection rewrite, duplicate-endpoint rejection, selection, selected/non-selected deletion, malformed cleanup, validation, and native error propagation.

### 2. Add saved-daemon CRUD and switching to the dashboard
- Add `client/src/components/ConnectionSheet.tsx`; no existing saved-connection editor exists, so copy `PairingSheet`'s React Native `Modal`, input, switch, destructive-button, and dark-theme patterns rather than introducing navigation or form dependencies. Exact props: `{ visible: boolean; store: ConnectionStore; onDismiss: () => void; onSelect: (endpoint: string) => Promise<void>; onSave: (originalEndpoint: string, replacement: Connection) => Promise<void>; onDelete: (endpoint: string) => Promise<void>; onAdd: () => void }`.
- The sheet title is `Daemon connections`. Each row shows `connection.name`, `connection.endpoint`, and `Selected` for the current endpoint, with explicit `Select`, `Edit`, and `Delete` actions. `Add daemon` dismisses this sheet and opens the existing `PairingSheet`. `Delete` requires `Alert.alert('Delete daemon?', 'Pairing credentials for this daemon will be removed from this device.', ...)`; deleting the final entry returns the dashboard to its existing unpaired empty state.
- `Edit` opens an in-sheet form with exact fields `Name`, `Endpoint`, `Fingerprint`, `Client name`, `Session token` (`secureTextEntry`), and `Skip fingerprint verification`. `Save changes` calls `updateConnection`; validation/conflict/storage failures remain in the editor and show `Alert.alert('Could not update daemon', message)`. Fingerprint and skip-verification remain stored metadata under current Expo transport behavior; do not add a second certificate-pinning implementation.
- In `client/app/index.tsx`, replace `connection` bootstrap with `ConnectionStore` plus `getConnection(store)`. Rename the destructive `Disconnect` action to `Daemons`; only explicit deletion removes credentials. Pairing authenticates, adds/preserves the display name described above, calls `saveConnection`, selects the result, and fetches sessions with the new token—subsequent launches load it without Auth-v2.
- Selecting a row calls `selectConnection`, clears the old session array, closes the sheet, creates `AgenticRemoteAPI` from the selected record, and refreshes. Editing the selected record also rebuilds the API and refreshes; editing another record leaves the current session list untouched. On a selected daemon's REST `401`, retain its saved record, clear only its visible sessions, and alert `Authentication expired. Pair this daemon again or edit its saved credentials.` so a stale token is recoverable instead of silently deleting the daemon.
- Correct `SessionSummary.state` in `client/src/protocol.ts` to the backend's documented literals `'running' | 'exited' | 'waiting' | 'idle'`. Build `visibleSessions` from `sessions.filter(session => session.state !== 'exited')` before applying the existing text search, so waiting and idle processes remain active while restored/naturally exited records never render. Remove the dead `'finished'` display branch/style.
- Bind child routes to the daemon that owns their data. Every terminal navigation and the Files action passes query param `connectionEndpoint: connection.endpoint`. `client/app/files.tsx` and `client/app/terminal/[id].tsx` call `loadConnections()` then `getConnection(store, connectionEndpoint)` rather than reading whichever daemon happens to be globally selected; missing/deleted endpoints alert and replace the route with `/` rather than contacting another daemon.
- Add `client/src/dashboard-route.test.tsx` using the existing `react-test-renderer`/Jest style. Cover initial restore without pairing, selecting daemon B and fetching B's sessions, re-pairing daemon A as an upsert, editing/deleting through the sheet callbacks, retaining a record after `401`, active-only rendering for `running`/`waiting`/`idle` versus `exited`, and terminal/files route params containing the selected endpoint.
- Add `client/src/components/ConnectionSheet.test.tsx` with `react-test-renderer`: assert the session-token input has `secureTextEntry`, Edit prefills all six stored fields and Save emits the complete replacement object, rejected `onSave` shows `Could not update daemon` and leaves the edit form mounted, delete requires confirmation and cancel does not call `onDelete`, and Select/Edit/Delete/Add invoke only their named callback.

### 3. Close terminal state deterministically on detach, manual close, and process exit
- In `client/app/terminal/[id].tsx`, pass an `onState` callback that reacts only to `exited`. Guard all terminal completion with `finishingRef` so a manual close and the emitted exit frame cannot issue duplicate REST closes or navigation. `connect(current)` constructs both the `SessionSocket` and a matching `AgenticRemoteAPI(current)` for the callback—do not rely on the asynchronously updated React `api` memo. Natural exit sequence: mark finishing, close the socket, `setOutput('')`, best-effort `currentAPI.closeSession(id)` to remove the daemon's exited record, then `router.replace('/')`; ignore `APIError` 404 as already removed, alert other cleanup errors, but still return because the PTY is already dead.
- Keep the `Close` confirmation. On confirmation, set the guard, await the endpoint-bound `api.closeSession(id)`, then close the socket, clear output, and `router.replace('/')`; if the request fails, clear the guard, show the existing `Could not close session` alert, and keep the terminal connected. The state callback is suppressed while the close request emits its `exited` frame, preventing a double close.
- Replace the header's direct `router.back()` with a detach handler: close the socket, clear output, and replace with `/` without calling `closeSession`, so a running command remains active and can be reopened. Unmount and background handlers remain socket-only cleanup; app foreground reconnect retains the existing complete-scrollback reset behavior.
- Expand `client/src/terminal-route.test.tsx` for endpoint-specific connection lookup and these observable paths: `exited` closes once, clears rendered terminal output, and replaces the route; manual Close closes once and replaces; 404 on exit still replaces; manual close failure stays; `‹ Sessions` detaches without REST close; cancel does nothing.

## Critical files & anchors
- `client/src/lib/connection.ts` — `Connection` and the three current single-record functions; this becomes the authoritative saved-daemon store and migration boundary.
- `client/app/index.tsx` — `Dashboard`, `connect`, `refresh`, `visibleSessions`, and `SessionCard`; all selection, CRUD, active-only filtering, and endpoint-bound navigation converge here.
- `client/app/terminal/[id].tsx` — `connect`, socket construction, and `close`; this owns idempotent exit/manual-close/detach behavior.
- `client/src/lib/session-socket.ts` — `SessionFrame` and `SessionSocket.onmessage`; current client literals say `finished`, while backend and `docs/protocol.md` emit `exited|waiting|idle|running`.
- `backend/internal/session/manager.go` — `List`, `Close`, `markExited`, and `restore`; reference only unless execution disproves current behavior. `Close` already deletes from the map, while natural exit/restore remains listed as `exited` and emits `session.state`.

## Assumptions & contingencies
- “Edit” intentionally means all stored fields, including the bearer token and fingerprint settings. The token input is masked, and storage remains SecureStore on native; web retains the repository's existing AsyncStorage security posture.
- “Disconnect from session” means detach: close/clear the local terminal and return to the list without terminating the daemon process. The explicit `Close` action terminates/removes it.
- Endpoint is the only confirmed daemon identity in the current pairing/session contracts. If implementation finds an undocumented stable daemon ID in an actual response, do not adopt it; preserve endpoint identity to keep migration and route contracts deterministic.
- No backend change is expected: active-only display is a client projection and terminal exit calls the existing close endpoint to purge the exited record. If the focused backend proof shows natural-exit cleanup cannot call `Close` idempotently, handle only `APIError` 404 as success in the terminal; do not add a new endpoint or compatibility protocol.
