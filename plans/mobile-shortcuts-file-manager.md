## Context
Fix terminal shortcut modifiers so tapping `Ctrl` or `Alt` and then typing on the Android/iOS software keyboard sends one combined terminal input (for example, `Ctrl` then `c` sends `\x03` and interrupts the process). Increase shortcut touch-target height while reserving layout space so the shortcut panel does not cover terminal output. Complete the existing authenticated daemon file-manager route with connection hostname, clickable breadcrumb navigation and refresh, parent navigation, directory/file rows, and an explicit close action returning to the session dashboard.

## Approach

### 1. Route software-keyboard input through shortcut modifier state
- Convert `ShortcutKeyboard` in `client/src/components/ShortcutKeyboard.tsx` to `forwardRef` and export `ShortcutKeyboardHandle = { input: (data: string) => void }`. Implement `input(data)` by applying existing `modifiedTerminalInput(data, modifier?.kind ?? null)`, calling the existing `onInput`, then clearing an unlocked modifier; keep long-press locked modifiers active. Route shortcut-key presses through this same method so shortcut buttons and Android/iOS software-keyboard characters share one transformation path.
- In `client/app/terminal/[id].tsx`, hold `useRef<ShortcutKeyboardHandle>(null)`, pass it to `ShortcutKeyboard`, and change the single-session `Terminal.onInput` callback to `data => shortcutKeyboardRef.current?.input(data)`. The handle then forwards transformed bytes to `SessionSocket.input`; no socket or wire-protocol change is needed.
- In `client/src/components/MultiTerminal.tsx`, add the same handle and route every visible `Terminal.onInput` through it before existing focused-session/broadcast dispatch. Preserve the current invariant: one-shot modifiers clear after the first input, locked modifiers remain, and broadcast mode sends the already-transformed bytes to all sessions.
- Failure/edge handling: multi-byte xterm sequences remain unchanged under `Ctrl`/`Alt`, matching current `modifiedTerminalInput`; if no focused multi-session exists, input remains ignored as it is now. Do not add special cases for `c`: the existing control-character mapping covers all one-character Ctrl combinations.

### 2. Make shortcut controls touch-sized without overlaying terminal
- In `client/src/components/ShortcutKeyboard.tsx`, remove absolute `dock` positioning and keyboard-height listeners. Render the shortcut panel in normal flex layout after terminal content so its measured height reduces terminal space instead of covering terminal output. Keep collapse/expand behavior; collapsed bar also remains in flow.
- Raise `key` and `modifier` minimum heights from 36 to 48 on Android-compatible touch targets; give collapse/show controls at least 48 height too. Keep horizontal `ScrollView` rows, current colors, labels, and 6-point spacing so increased height does not force keys wider or hide keys.
- In both the single terminal route and `MultiTerminal`, retain existing safe-area `bottomInset` padding. Software keyboard remains platform-managed; removal of manual `bottom: keyboardHeight` avoids double-offset gaps when the app window already responds to IME insets.

### 3. Complete authenticated file-manager navigation and listing
- Keep `client/app/files.tsx` as the sole file-manager route and reuse existing `AgenticRemoteAPI.files`, `searchFiles`, `gitStatus`, `readFile`, and `writeFile`; backend handlers and protocol types already provide the requested daemon connection, so add no endpoint or dependency.
- Store the resolved `Connection` alongside the current `AgenticRemoteAPI`. Display `new URL(connection.endpoint).host` as the header title. Replace the current header back arrow with a close button using Feather `x`, accessibility label `Close file manager`, and `router.replace('/')` so close always returns to session manager rather than depending on route history. Keep refresh as a separate header action.
- Replace editable `Workspace path` input with a horizontally scrollable breadcrumb row derived from normalized slash-separated `path`. Render root as `Workspace`, then each directory name separated by Feather `chevron-right`. Each segment is a pressable 44×44 minimum target: root loads `''`; an earlier segment loads its prefix; the last segment calls the same navigation function and therefore refreshes the current directory. Navigation clears search before loading.
- Add a parent-directory pressable above the list with Feather `corner-up-left`, label `Parent directory`, and a disabled/dimmed state at root. For `a/b/c`, it loads `a/b`; for one segment it loads `''`. This is independent of breadcrumb taps but uses the same navigation function.
- Render existing `entries` with the already-imported `FlatList`. Each row is a minimum-64-height `Pressable`: folder/file Feather icon, `entry.name`, optional relative path during search, optional git code from existing `gitCodes`, and file size for files. Pressing a directory navigates into `entry.path`; pressing a file opens the existing `Editor` through `api.readFile(entry.path)`. Use `entry.path` as key. Keep current search input; submit reloads current directory, and empty query restores directory listing.
- Show existing `ActivityIndicator` while loading, `No files in this directory` for an empty normal listing, and `No matching files` for empty search. On list/search/read/git failure, preserve current directory and existing entries, stop loading, and show the existing alert. Ignore stale responses by adding a monotonic request ref so rapid breadcrumb/directory taps cannot let an older response overwrite the latest location.
- When leaving `Editor`, reload the current directory so saved file metadata/git status is current. Preserve SHA-256 conflict handling through existing `writeFile`; no delete, rename, upload, or new-file UI is added because user requested browsing/navigation, not destructive operations.

## Critical files & anchors
- `client/src/components/ShortcutKeyboard.tsx` — `modifiedTerminalInput`, modifier lock state, keyboard listeners, and absolute `dock` styling are the root of combination/layout behavior.
- `client/app/terminal/[id].tsx` — single-session `Terminal` and `ShortcutKeyboard` currently dispatch independently to the same socket.
- `client/src/components/MultiTerminal.tsx` — focused/broadcast input routing must apply the same modifier transform exactly once.
- `client/app/files.tsx` — existing authenticated but incomplete file route; API state loads while `entries` and `FlatList` are currently unused.
- `client/src/lib/api.ts` — existing authenticated filesystem methods; reuse without protocol changes.

## Assumptions & contingencies
- “Hostname” means the network host (including explicit port) from `new URL(connection.endpoint).host`, matching dashboard behavior; no daemon hostname exists in backend protocol. If execution discovers a newly added authenticated daemon-hostname field, prefer that field and fall back to URL host.
- Breadcrumb root label is `Workspace`, because daemon paths are workspace-relative and the backend intentionally hides the absolute host filesystem root.
- Existing file editor remains available and unchanged except post-save refresh. No destructive file actions are exposed.
- If normal-flow shortcut layout does not stay above the iOS software keyboard during device smoke testing, wrap terminal-plus-shortcuts in the route’s already-imported `KeyboardAvoidingView` with `behavior={Platform.OS === 'ios' ? 'padding' : undefined}`; do not restore absolute positioning or manual keyboard-height offsets.
